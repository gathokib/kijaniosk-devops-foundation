# DevOps Delivery Notes

## Flow
The team will use Git branches to organize development work. Changes will be developed on feature branches, reviewed through pull requests, and merged into the develop branch before being promoted to main.

## Feedback
Pull requests provide an opportunity for team members to review changes before they are merged. Feedback from reviews will be used to identify errors, improve documentation, and maintain consistent engineering practices.

## Learning
The team will continuously learn from implementation challenges, code reviews, and infrastructure decisions. Lessons learned will be documented and used to improve future development and deployment work.

## Delivery Approach
The KijaniKiosk project will follow a simple DevOps workflow:

1. Create a feature branch.
2. Make and test changes.
3. Commit the changes.
4. Create a pull request to develop.
5. Review and address feedback.
6. Merge into develop.
7. Promote stable changes to main.
